## 4. 草稿、反馈与批量结果

建议独立保存三类数据：目标草稿、带来源/有效期的设备反馈、最近命令结果。草稿以关节 ID 索引，记录编辑版本；收到反馈只更新反馈层，切换视图与加载新状态不会覆盖用户输入。

流程为：编辑多个目标 → 检查范围、单位、限位和控制权 → 显式应用 → 显示总体与逐关节结果。发送时快照化本次草稿，后续继续编辑不会改变在途命令。未选关节不发送；部分失败不得被总体“成功”掩盖。接收、写入/应用、反馈确认与到达目标是不同阶段，必须按实际可证实能力命名，不能凭点击生成成功。

未得到有效校准时显示 ticks。草稿可以设计，但可执行滑块范围必须来自验证过的设备/映射/校准信息；不沿用现有左膝样例的 112–136。角度转换需要零位、方向、比例及限位；缺失时不标成准确度数、不自动裁剪后执行。

左右联动在已验证的语义角度或相对姿态中做镜像，再经各侧方向、零位和比例转换回 ticks。镜像符号与基准需逐对核对，不能凭名称猜符号，也不能直接复制原始 ticks；校准不足时镜像不可用。

“当前位置填充”只使用有效反馈，并明确影响范围及跳过结果。“保存姿态”记录映射、校准、单位和目标。“加载姿态”检查版本与范围，只改草稿，绝不自动发送；不兼容项目逐项提示。断线/重连不执行旧草稿、不重放命令、不自动使能。

现阶段不设计连续发送默认行为。批量写入不保证物理时间上的绝对同步，后续依设备能力明确时序。
