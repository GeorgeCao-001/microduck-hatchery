# Microduck Hatchery 日志与记录

此目录保存项目过程记录，并规定运行诊断和实验产物的存放方式。当前实际文件为本说明与 [PROJECT_LOG.md](PROJECT_LOG.md)；不表示已产生机器人运行日志或正式实验记录。

| 类型 | 存放与规则 | Git 处理 |
|---|---|---|
| 项目开发记录 | `PROJECT_LOG.md`：具体变更、目的、验证范围、未完成项；作为唯一开发记录主文件 | 小型 Markdown 可跟踪 |
| 本机临时验证 | 仓库 `.local/`：静态预览输出、浏览器截图和 QA 产物；现有 Web 状态页链接这些证据 | 已忽略，不自动移入正式记录 |
| 设备运行诊断 | 设备端系统日志；需导出时再建立 `logs/runtime/` | 导出文件默认忽略 |
| 实验元信息与摘要 | 有真实实验时再建立 `logs/experiments/`，记录源码/模型/策略/校准版本、参数、平台与结果 | 可分享的小型元信息可跟踪 |
| 大型实验数据 | `logs/experiments/raw/` 与 `logs/experiments/artifacts/`：原始轨迹、权重、视频及其他生成文件 | 默认忽略；摘要引用可恢复的存储位置与校验值 |

`docs/` 描述当前有效方案和操作方式；本目录记录已发生的工作。更新同一机制时修改其主文档，开发记录链接过去，避免复制一套相互漂移的定义。

重要变更完成后更新唯一项目记录，列明涉及文件、目的、实际验证和剩余事项。

设备服务日志优先使用 stderr/stdout 与系统日志设施，实际部署后核对保留策略；官方 `robotd` 单元采用 journald，可作为参考。[官方服务单元](https://github.com/pollen-robotics/microduck/blob/9136aa4ee88e81edf2bcaf3527e90b65da25f1eb/robotd/systemd/robotd.service)

源码仓库的 `logs/` 不是设备运行时固定写入路径。没有验证我们设备上的日志重启/断电持久性，不依据官方或来源作者的镜像测试作保证。正式实验记录另行定义元信息、样本和事件，不能用纯文本调试日志代替。

记录必须明确区分样例、模拟、真实设备，以及来源作者结果和我们自己的结果。回放和日志查看只读，不触发历史目标执行；采集与磁盘写入不阻塞设备控制循环。导出诊断时只保留必要字段，不记录令牌、私钥或网络密码。
