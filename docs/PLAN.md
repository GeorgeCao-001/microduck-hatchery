阶段 1 的具体迁移以审查过的路径清单为依据，不因目录已准备就自动导入官方实现。新增依赖、部署和实机控制另按授权推进。模型与硬件核对可以并行，策略执行须等待设备基线与兼容确认。

## Web 并行工作

`web/` 是 Hatchery 自己的前端。官方 `mediad/webclient` 只作为控制语义与通信参考；正式权威保持 gateway → protocol / RPC → robotd → duck-control / safety。

[七章教程](../web/docs/LOCAL_REVIEW_PROPOSAL.md) 继续先审查，再实现页面。[联调样例](../web/docs/JOINT_COORDINATION.md) 已按授权实现关节大面板与连续样例曲线，不连接设备或发送目标。15 个关节含嘴部按左腿、右腿、头颈与嘴部分组三组各五张卡片，保留滑块和数字输入，联调无内部列表滚动；单关节调试继续保留独立滚动列表。草稿与反馈分离，加载姿态只改已选草稿。

桌面调节与大曲线并排，窄屏堆叠；正常字号的导航和曲线设置可收起。曲线关节选择独立于草稿应用范围，位置/目标回读、误差、raw load、电压、温度按单位分图。当前仅左膝有浏览器生成样例，其他关节与 raw load 缺测；有界历史、暂停绘图和浏览器相对时间只用于前端检查，不能替代阶段 2 的真实状态、设备时钟与失联协议。

七章包括运控、仿真、RL、标准导出、FT 运行时与实机验证，不扩为大量平铺章节。

生产前端栈尚未冻结。当前原生原型继续使用；缺少 `app.js` 的样例诊断页不是已完成的正式连接界面。补页面脚本、协议 schema 和干净环境依赖属于后续功能收尾，联调样例不修复这些独立缺口。

## 后续能力

USB-C gadget 网络、BLE 本地桥、媒体、手柄、ToF、OTA 等已有对应模块位置，按需求逐步实现，不要求一起启动。WiFi / USB / BLE 与 Windows / Linux / macOS 分别验收，BLE 不默认承担高频运动控制。

设备接入前核实 Radxa 镜像、FT 型号与固件、全部 15 个 ID、校准方向/零位/限位、HOME、FT 运行时与 IMU 配套版本、串口所有者及恢复路径。摄像头、I2C、UART、GPIO 等节点不能沿用官方假设。

当前实际完成情况见 [LOCAL_STATUS.md](../web/docs/LOCAL_STATUS.md)，目录边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。
