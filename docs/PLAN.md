# Microduck Hatchery 分阶段计划

按 [架构 v2](microduck-hatchery-architecture-v2.md) 渐进推进，保留官方运行职责与 crate 边界，硬件适配以实际 Radxa / FT 平台为准。目录存在不表示模块已实现。

## 必需主线

| 阶段 | 输出 | 进入下一阶段的条件 |
|---|---|---|
| 0 · 本地结构 | daemons / libraries / protocol / tools 位置，hooks / scripts / spaces，独立样例工具与文档入口 | 已建立说明位置与 Python 样例入口；未自动迁入官方源码，后续只读 workspace 见阶段 1。 |
| 1 · 来源与路径 | 经授权后引入固定来源的完整 crate；逐项修正 workspace、path dependency、脚本、hooks、systemd、CI、测试资源 | 已核对 FT 冻结来源并建立 4 成员只读 workspace；完整官方 crate 仍未迁入，构建与硬件运行分别验收。 |
| 2 · 协议与只读 | 核对 shared protocol / RPC、板端 gateway 与 robotd；15 关节、单位、时钟、来源、会话、有效期 | 实物型号、固件、节点与总线所有者明确；只读不绕开 robotd 直接轮询；样例和真实来源可区分。 |
| 3 · 有限台架控制 | duck-control / safety 裁定校准、限位、控制权、模式、期限与确认；先单关节再逐关节批量 | 所有入口统一门控；校准与 robotd 互斥；停止、失联和重连行为经核对，重连不补发旧目标。 |
| 4 · 模型与标准导出 | 保留所选训练源码结构，固定模型、仿真、RL、评估及标准策略产物 | 观察/动作映射、HOME、归一化、缩放、IMU 坐标、频率和运行时兼容逐项有证据。 |
| 5 · FT 实机闭环 | FT 总线/IO 适配、配套 IMU、读取/推理/写入；台架到站立、低速行走与转向 | 实物闭环可重复，正式元信息和实验结果可追溯；来源作者结果不替代团队验收。 |

阶段 1 的具体迁移以审查过的路径清单为依据，不因目录已准备就自动导入官方实现。新增依赖、部署和实机控制另按授权推进。模型与硬件核对可以并行，策略执行须等待设备基线与兼容确认。

## Web 并行工作

`web/` 是 Hatchery 自己的前端。官方 `mediad/webclient` 只作为控制语义与通信参考；正式权威保持 gateway → protocol / RPC → robotd → duck-control / safety。

2026-10-07 已按授权实现 [左侧只读 3D 与右侧长滑块联调](../web/docs/LOCAL_REVIEW_PROPOSAL.md#10-截图式联调布局与只读-3d已实现样例)：联调/单舵机调试同属“舵机”，曲线作为调试台内独立页面。路由、目标交互、样例采集、绘图及 3D 保持独立模块；本地 Three.js 与参考模型只用于展示，无浏览器 RL / 物理仿真依赖。

**总控界面（整机总览与全局操作）尚未实现。** [总控方案](../web/docs/LOCAL_REVIEW_PROPOSAL.md#8-总控界面方案待审查) 仍待审查，独立样例页覆盖整机状态、控制资格、15 关节/校准概览、健康告警、全局操作和整机事件。顶部样例状态栏及设备/传感器占位提示不算总控完成；首轮真实操作禁用，缺测保留未知，不等待或冒充正式设备链路。

[七章教程](../web/docs/LOCAL_REVIEW_PROPOSAL.md) 继续先审查，再实现页面。[联调样例](../web/docs/JOINT_COORDINATION.md) 不连接设备或发送目标。15 个关节含嘴部按左腿、右腿、头颈与嘴部分组三组各五条紧凑行，保留滑块、数字输入与独立实测标记，联调无内部列表滚动；单舵机调试继续保留独立滚动列表与详情。草稿与反馈分离，加载姿态只改已选草稿。

3D 支持目标草稿/样例反馈切换、相机旋转/缩放/复位和关节选中。缺测关节保留灰色透明中性参考姿态，不当作实测零位；嘴部估计铰链存在。样例 ticks 到角度是独立视觉映射，正式校准与本机外形仍待核对；[几何与库许可](../web/licenses/microduck-model-NOTICE.md) 分开说明。离开联调销毁渲染资源，切页不影响共享采集或草稿。

曲线独立占用工作区；正常字号的导航和曲线设置可收起。曲线关节选择独立于草稿应用范围，位置/目标回读、误差、raw load、电压、温度按单位分图。当前仅左膝有浏览器生成样例，其他关节与 raw load 缺测。调试台内切页保持采集与草稿，暂停只冻结绘图，离开调试台才停止采集；有界历史和浏览器相对时间只用于前端检查，不能替代阶段 2 的真实状态、设备时钟与失联协议。

七章包括运控、仿真、RL、标准导出、FT 运行时与实机验证，不扩为大量平铺章节。

生产前端栈尚未冻结。当前原生原型继续使用；缺少 `app.js` 的样例诊断页不是已完成的正式连接界面。补页面脚本、协议 schema 和干净环境依赖属于后续功能收尾，联调样例不修复这些独立缺口。

## 后续能力

### FD1985 完整调试与 HD-1910 标定（已批准分阶段推进）

2026-10-10 已确认 15 颗均为 HD-1910-C001。**Radxa Zero 3W 是整机主要平台**；FE-URT2-C001 当前接 Windows 用于台架维护，辅助入口优先 Windows / macOS，Linux 桌面与 Radxa 分别验收。[接入方案](../web/docs/FD1985_INTEGRATION_PROPOSAL.md)保留完整 FD 功能目标，并增加逐关节批量工作流。

按审查 → 型号规格 / 双单位只读 UI → 权威后端与真实只读 → 逐关节标定及有限控制 → 完整调试 / 维护 → Linux / 板端扩展推进。原始值、编码器参考角和实际标定角分别保存；未知零位、方向、限位及寄存器单位不补默认值，现有演示数据不改成实测。FD 旧文件、升级及在线接口的兼容性仍需资料和验证，不能宣布全部可用。

阶段 B 已完成前端参考角、参数 / 软件标定草稿、逐关节批量差异与 JSON 导入导出；阶段 C 已增加独立的只读诊断快照，维护操作仍禁用。真实角度未知，草稿不写入设备、不改变联调目标、曲线或 3D。使用与本团队验证见 [联调说明](../web/docs/JOINT_COORDINATION.md#参数与软件标定草稿) 和 [状态报告](../web/docs/LOCAL_STATUS.md)。

阶段 C 的软件基础已建立：隔离 Rust 工具链、锁定依赖、4 个 crate、最小 robotd / gateway、冻结 FT 只读包和主机接收时间。Windows 已构建并用 fixture 验证，目标源码检查与实机结果分列。下一步核对实际 HD 固件 / 内存表、15 个 ID，再验收真实读取、串口独占、超时与拔插；不自动打开端口或发送控制。使用见 [维护后端](MAINTENANCE_BACKEND.md)。完整 Radxa 运行仍为主线，gateway / tools 只负责传输 / 启动，现有 Python 样例不接管总线，不迁入其他服务或新建 drivers framework。

### Web 模型导入与轻量物理（后置，未实施）

2026-10-07 最新用户决定：当前 3D 继续用于目标草稿 / 样例反馈的姿态可视化，模型导入和内置轻量物理留待后续有时间再做。本轮仅补充计划，不新增导入入口、物理引擎或依赖。早期文档中不做浏览器物理仿真的范围约束仅适用于当前阶段，后续范围以本节为准。

1. **先做实际模型导入与关节联动。** 优先 MJCF / MuJoCo XML + STL，再支持 URDF；本地文件夹或 ZIP 连同引用资源一起导入。核对单位、坐标、关节轴、零位、限位和 15 个舵机 ID，嘴部必须保留。单独 STL 先用于外形查看，关节及物理参数需要另外提供。
2. **随后增加可开关的轻量物理预览。** 先做重力、地面碰撞、暂停与复位，再逐步加入简化碰撞体、质量惯量和关节约束。模拟结果独立于目标草稿、设备反馈及曲线来源，不覆盖草稿或触发实机命令。

模型解析、姿态映射、渲染和物理预览保持独立模块；新增库与参数支持范围在实施前评估，不冻结生产栈。浏览器预览不替代整机仿真 / RL 主线，也不能作为 FT 舵机性能、步态或实机安全的验收依据。Web 实施细项见 [后续建议](../web/NEXT_STEPS.md#后续-3d-扩展后置未实施)。

### 设备扩展与接入准备

USB-C gadget 网络、BLE 本地桥、媒体、手柄、ToF、OTA 等已有对应模块位置，按需求逐步实现，不要求一起启动。WiFi / USB / BLE 与 Windows / Linux / macOS 分别验收，BLE 不默认承担高频运动控制。

设备接入前核实 Radxa 镜像、FT 型号与固件、全部 15 个 ID、校准方向/零位/限位、HOME、FT 运行时与 IMU 配套版本、串口所有者及恢复路径。摄像头、I2C、UART、GPIO 等节点不能沿用官方假设。

当前实际完成情况见 [LOCAL_STATUS.md](../web/docs/LOCAL_STATUS.md)，目录边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。
