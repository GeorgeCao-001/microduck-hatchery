# 官方源码迁移与 Hatchery Web 接入执行计划

更新日期：2026-10-18（Asia/Shanghai）。本文件是本轮详细执行与进度主表；[PLAN](PLAN.md) 保留全栈长期主线，[项目日志](../logs/PROJECT_LOG.md) 记录实际发生的变更。

## 1. 交付目标与执行范围

补齐官方运行服务、协议、库、工具、Spaces、安装 hooks 与发布链路，按既有 v2 分类保留完整 crate 和上游内部结构。将用户可操作的能力接入现有 Hatchery Web，让 Radxa 可通过浏览器完成观察、配置及条件满足后的控制；设备权威继续在官方 daemon 与 duck-control 中。

本次交付为计划、依赖分析、Web 接入矩阵、任务与验收定义，不在本次文档工作中导入剩余源码、增加运行依赖、部署、切换网络或控制硬件。执行阶段按本计划逐包推进，不因前一个硬件验收待用户执行而停止无关的软件迁移。

必须保留的用户决定：

- U1：以官方实现为先，保留项目结构；新增代码主要用于路径、FT 硬件和现有 Web 的接口适配。每处自定义逻辑说明上游缺口及替代方案。
- U2：Radxa Zero 3W 是运行平台；实际选型为 IMX219、HD-1910-C001、FE-URT2、LSM6DSV16X 与 ToF 模块。型号、固件、接线以硬件资料和实物确认，不能沿用官方 beta 板或 Dynamixel 假设。
- U3：保留全部 15 个物理关节含嘴部，物理／运行时／策略顺序分开。任意实际总线 ID 可扫描、回读与调试，不要求先归类。
- U4：ID、关节关联、设备参数与标定的修改统一在“参数与标定”；其他舵机页读取同一份已生效配置，不另设编辑入口。
- U5：沿用原浅色风格和现有导航，设备位于总控与舵机之间；当前不做多设备入口。相机位于传感器上方，IMU／ToF 在下方保持紧凑，ToF 格子为正方形；系统轨迹不塞进传感器页。
- U6：相机基础区保持简短，高级参数折叠，采集帧率／分辨率／模式只读；能力来自实际后端，不能用页面滤镜假装更改相机参数。
- U7：板上测试由用户执行；本地构建、模拟与类型检查分别记录，不代替 Radxa 的画面、连接和动作验收。
- U8：所有阶段有依据、可见进度及可复现交付；不擅自提交、推送、发布或修改用户系统。

## 4. Web 接入矩阵

用户能力放入现有总控、设备、舵机、传感器与设置区域。服务卡片显示程序运行状态，功能页展示用户要完成的事。普通使用区不铺满 PID、socket、寄存器地址；技术详情折叠。新增子区的具体路由在 M2 确定，不扩展多设备导航。

下表 RPC 为当前协议中已确认的语义，执行时必须再次核对所选基线的 handler 与权限；没有正式方法的项目明确列为待适配，不能按名字猜接口。

| 服务／能力 | Web 位置与交互 | 权威后端／依据 | 接入要求 |
|---|---|---|---|
| robotd 状态 | 总控健康／运行模式；舵机真实反馈、曲线与 3D | `robot.state`／`robot.subscribe`，E4、E8 | 区分关节实测、目标、草稿和缺测；FT 不支持的量保持未知 |
| 舵机配置与标定 | 舵机→参数与标定：扫描、任意 ID、关联、参数、零位／方向／限位、保存与回读 | 现有维护接口及 robotd／duck-control，E8 | 唯一编辑入口；其他页仅读取已生效映射，保存失败不冒充生效 |
| mediad 视频／ISP | 传感器→相机：直播、截图、基础参数与折叠高级参数 | 官方 WebRTC、`media.video`、本地相机能力接口，E4、E6 | 不重开采集器；目标 FPS 与实测 FPS 分开；驱动能力不足时说明具体原因 |
| duck-detect | 相机内可开关检测框、目标数／置信度／方向，折叠性能与模型信息 | mediad 检测通知，E11 | 不把框大小换算成未经标定的绝对距离；关闭叠加不自动启停推理 |
| tofd | 传感器→紧凑 ToF：8×8、最近／中心距离、有效区、状态 | `tof.stream`／`tof.frame`，E4、E9 | 无效分区保持缺测，断线不保留成实时值，正方形单元格 |
| 实际 IMU | 传感器→紧凑 IMU：姿态、原始量、方向／融合状态 | robotd 的真实 IMU 状态，E5、E9 | 确认芯片／总线／量程／坐标；不新建重复采集 daemon，不沿用模拟姿态 |
| configd 网络／蓝牙 | 设备→Wi-Fi／蓝牙选择、密码、扫描、连接／断开／忘记 | `net.*`、`pad.*` 及已有扩展，E7 | 结果以实际状态确认，保留当前密码清理、会话去重与失败不重发；校园网 802.1X 未支持时明确显示 |
| configd 身份／配对 | 设备设置→设备名称、配对配置 | `system.info`／`system.setName`／配对 PIN 相关方法，E4、E7 | 区分浏览器显示别名与板端持久名称；密钥不进入日志或导出 |
| 系统服务与诊断 | 设备→服务运行状态，详情中查看版本、失败原因与日志 | `system.services`／`system.logs`，现有进程观察，E4、E7 | systemd inactive＋进程存在显示独立运行；安装／运行／就绪／能力分别显示 |
| btd／duck-ble | 设备→蓝牙详情：BLE 服务、配对／认证状态和连接情况 | 官方 btd／duck-ble，E7 | 浏览器经板端服务管理；无需以 Web Bluetooth 作为通用前提，不冒充普通蓝牙音频支持 |
| padd／pad-map／netpadd | 设备→输入设备：手柄连接、按键／摇杆观察、映射与输入源选择；总控显示当前控制来源 | `pad.status`／`pad.input`／`pad.report`／绑定语义，E10 | 保留官方输入映射和 deadman；Web 不直接发 UDP 到控制口，不与实体手柄争抢控制 |
| nfcd（可选） | 设备详情→读卡器连接／最近配对结果 | 官方 NFC→configd 配对链，E10 | 无读卡器时显示未配置；如上游无观察 RPC，先审查最小只读接口，不把日志文本解析成控制 API |
| updaterd | 设备→软件更新：版本、检查、进度、结果、可选回滚与诊断 | `update.check/status/subscribe/apply/rollback` 等，E12 | 安装与回滚须显式操作，通过官方可重启性与健康检查；下载完成不等于升级成功 |
| 检测模型／策略管理 | 相机高级区显示检测模型；设备设置显示已安装策略与兼容信息 | `detector.*`／`policy.*`、robotd 策略状态，E4、E12 | 版本、哈希与兼容性来自后端；安装模型不自动启动策略或动作 |
| 声音与声音检测（有硬件时） | 总控简短声音操作、设备中音频可用性；原始诊断折叠 | `robot.sound`、已迁入 sounds／pet-detect，E4、E5 | 无已确认麦克风／扬声器时不可用；声音检测不是视觉，不放进相机页 |
| Spaces／视觉示例 | 复用 vision-demo 的处理逻辑进入相机高级工具；远程示例保留独立运行入口 | E11 | Hatchery 保持自己的页面；不把整个 Gradio／策略演示页面塞进 iframe |
| hooks／xtask／训练 | Web 显示产生的版本、更新阶段、兼容性与结果 | E12、E13 | 没有任意 shell／任意 hook 执行按钮；编译和训练在对应工具环境运行 |

服务面板的固定名单随真实迁入范围扩充：robotd、mediad、configd、updaterd、btd、padd、tofd；netpadd、nfcd 仅在对应模块纳入后显示。RKAIQ 显示真实服务与进程身份，不能把同进程参数接口画成新 daemon。

## 6. 验证与交付规则

每个任务分别记录五种状态，不用一个“已完成”混在一起：

| 维度 | 允许状态 | 达成依据 |
|---|---|---|
| 源码 | 待迁入／已迁入／待对齐 | 原始文件、完整 SHA、哈希、许可及修改记录 |
| 本地软件 | 未验证／进行中／通过／失败 | 对应版本的实际命令和结果；省略的原生链接／平台必须标出 |
| Web | 不适用／待接入／接口完成／交互验证通过 | 真实后端契约、页面操作、失败／离页／断线核对；模拟必须说明 |
| Radxa | 待用户验收／通过／失败／缺硬件 | 用户回传的版本、系统、设备信息及结果 |
| 部署 | 未安装／前台可运行／隔离安装通过／用户板端通过 | 实际安装与恢复证据；复制服务文件不等于安装完成 |

一个任务只有在其承诺的软件交付与 Web 验证通过后，才可记为“软件完成”。任务承诺含实机动作／成像／连接／升级时，另需对应 Radxa 证据才能记为“整体验收通过”。无硬件的模块可以交付源码与软件检查，仍保持硬件缺项。

检查选择：纯文档核对链接和事实；协议／驱动改动检查边界、未知值、超时和应答；异步 UI 检查重复提交、焦点／草稿、迟到回包与资源释放；hooks 在临时目标或隔离环境核对幂等／错误恢复。测试脚本、截图和临时日志放系统 TEMP，不向工作区写冒烟日志。项目日志只留摘要和必要证据位置，敏感原始数据不入库。

默认构建利用已有 Cargo 缓存，给增量命令；不要求每次全量重编译或同时安装全部工具。模型、外部运行库和源码依赖分别列明下载大小与用途，给现有代理／镜像的传递方式，安装工具不能静默清掉用户代理配置。并行数依据板端内存和实际构建反馈选择，不在文档里假定只能 `-j 1`。
